# 2008 官网栏目与静态资源恢复

来源：用户在首版离线镜像验收后指出 Current News 条目图片缺失，GAME GUIDE、MEDIA 等侧栏条目返回 `Offline route rejected / non-canonical route is not allowed`，要求完整下载恢复。当前任务在原有 [离线重建](offline-reconstruction-2008.md) 基础上继续，原始来源及第一版便携包保留。

## 范围与判定

先恢复旧官网侧栏的公开页面及其图片、样式、脚本等静态依赖，再跟随已取得内容发现后续公开正文和嵌套静态依赖。以 `20080512210044` 为基准，优先基准前相近 90 日，其他 2008 捕获需单列；更早或迁站后的文件不自动混入基准。账号支付、Armory、社交、遥测、依赖在线提交的功能及大型客户端/视频下载不展开为普通页面。

“完整”按真实链接和依赖清单验收，不能以占位响应的 HTTP 200 计数：须分别记录可用原件、已证明错误内容、无合适捕获、网络获取失败、未尝试和明确排除。确实无法从存档恢复的项目保留证据与缺口，不能用现代素材替代。

## 预算与下载约束

完整工作区上限 14,000,000,000 bytes；D 盘保留至少 10 GiB，另留 256 MiB 裕量。开始时工作区约 325 MB，D 盘余量约 14.3 GB，因此实际空间余量以运行时磁盘检查为准。最多两个 Archive 请求流，页面与静态资源各一个；每批有请求数、时间和单实体上限，连续三次站点失败停止该批。有限批次可续传，不反复请求已验证成功或相同失败且没有新依据的实体。

## 已复现与工具调整

首版服务对 `/info/`、`/media/`、`/info/story/` 返回 400，而已配置别名的 `/downloads/` 正常；问题包含路由层误判，不能仅靠新增文件解决。

此前两项 gzip 解码失败未保留 HTTP 元数据，无法区分服务器编码问题和捕获本身。下载器改为请求 identity 传输，仍验证真正的 gzip/deflate，并拒绝截断压缩实体；解码失败保留状态、最终 URL 和响应头。9 项下载器测试通过，实际恢复是否成功仍以新网络证据为准。

本文件在任务进行中更新实际结果；计划、下载成功、内容有效和浏览验收分别记录。

下载器后续通过一项原始 wire 证据确认 `burningcrusade/faq.html` 的响应头标记 gzip，但实体实际为明文 HTML，完整实体的 SHA1 Base32 与 CDX 摘要一致。新增计划字段 `cdx_digest`：只有已提供独立 CDX 摘要且完整实体严格匹配时，才接受此类错误 gzip 头；保留原始响应头，并在 manifest 单列解释。摘要不匹配、无独立摘要或真正 gzip 截断仍拒绝。11 项下载器测试通过，包含该实际证据及摘要不符的负例，证据位于 `research/site-recovery-2008/wire-diagnostics/`。

页面下载执行由原清单执行者交接给工具执行者，继续覆盖全部有限候选及 CDX 截断项；根仍负责批准 map、构建与最终验收，静态资源执行者保持独立目录和两条请求流。交接时页面33项、静态资源186项，均属中间成果。

## 路由修复后的实测与专项调研

修复服务已在原端口 8765 重新启动。实际请求 `/info/`、`/media/`、`/info/story/` 已从误报 400 变成明确未收录的 404；`/downloads/` 与百科首页仍为 200，两个编码越界负例仍为 400。证据见 `research/offline-2008/route-recovery/root-live-probe.json`。404 仍代表文件尚待获取，不能计为已恢复栏目。

用户追加授权两个 GPT-6.1 Sol xhigh 独立对话，分别调研 Wayback 查询与下载方法、2008 官网组织结构；文件所有权分别为 `research/sol-wayback-methods/`、`docs/sol-wayback-methods.md` 和 `research/sol-wow-structure/`、`docs/sol-wow-structure.md`。两者不增加批量 Archive 请求流，当前主任务继续下载。

批量 CDX 的初次 `showNumPages=true` 请求返回表头与空字段，并非实际捕获列表；该结果不能证明没有捕获。去掉该参数后的 `/info/` 查询已得到真实捕获记录，第一批候选出现 61 项可选捕获。原响应保留为方法修正证据；后续完整性结论以实际记录、下载实体与浏览结果分别验证。

## 吞吐调整

资源首批 900 秒仅取得约 38 项、页面批次 600 秒约 20 余项，单请求延迟约 24 秒。为完成已有全量队列，总 Archive 请求流由最初的 2 调整为最多 4：页面、静态资源各 2 个互斥分片，各自使用独立 BackupRunner 与 ZIP 目录，不引入共享 ZIP 并发写。每分片保留有限时间/请求数、连续站点失败停止与原磁盘约束；已成功 URL 不再次请求。最初两流约束是本任务的节流设计，现依据实测吞吐修订，空间和时间选版规则不变。

专项方法报告 `docs/sol-wayback-methods.md` 已完成：downloads/news 的初次 CDX 各达到 20,000 行上限，当前枚举不能声称完整；digest collapse 可能损失最近日期或同内容邻接 URL。新增缺口判断必须通过无 collapse 的精确查询或已闭合的有界分片证明，不能把查询上限当无捕获。
