# Warcraft Encyclopedia 2008 基准、资源恢复与方法史

**日期约定（修订）：**本文所有捕获日期、时间戳和回放时刻均按 UTC 书写；2008 基准为 20080512210044 UTC，2010 候选为 20101203214958 UTC。

本文记录本项目如何从“寻找最新可用的官方百科”转为保存可审计的 2008 基准镜像，以及最终交付物的能力边界。它是方法和证据索引，不是原始响应的替代品；原始实体、清单、校验报告和构建产物仍以仓库中的报告为准。

## 一、基准选择：可保存不等于可浏览

项目最初以 2010-12-03 UTC 的官方百科入口（候选捕获时间戳 20101203214958，亦为 UTC）作为最晚候选。这个候选的正文实体、长度和内容摘要可以保存，首页也包含完整的百科入口内容，但它以 application/xhtml+xml 返回，首部的 xml-stylesheet 处理指令缺少正常结束标记。严格 XML 解析器因此报告 ParsePI: PI xml-stylesheet never end；同一实体在浏览器和页面抽取器中的表现也不稳定。HTTP 200 和内容相似度不能单独证明页面可用。

用户提供的 2008-05-12 21:00:44 UTC（捕获时间戳 20080512210044）回放以 text/html 返回，浏览器和页面抽取均能得到目录和词条主体。重新核验确认，2010 候选应撤回“最晚可用”的结论，改作保留的同站晚期参考；2008-05-12 21:00:44 UTC 成为第一阶段基准锚点。过程、MIME 对照、Firecrawl 复核和下载比较见[2008 基准复核](reassessment-2008.md)。

这次纠正也确定了保存原则：XML 文件名不代表内容一定是 XML，HTTP MIME、字节签名、解析根节点和实际浏览行为必须分别记录；页面能被转换器读出若干文字，也不能替代完整的页面交互验收。2010 的原件仍保留，便于比较 XSL、主题和内容差异，但不作为本项目“可浏览基准”的证明。

Thuum 分片提供了有用的结构参照：101,089 个文件、3,062,212,968 字节，其中 100,722 个 HTML、3,025,051,284 字节的扫描结果说明百科和周边站点可能形成很大的路径集合；压缩体积很小只说明压缩效果，不说明所有响应都是成功的 HTML，也不说明每个 URL 都属于百科展示范围。因此本项目优先保存原始实体、请求来源、依赖边和验证结果，而没有把一个大型分片当作可直接发布的全站 HTML。

## 二、五层证据模型

**Thuum 数值依据：**结构复核的只读扫描为 101,089 个文件、3,062,212,968 字节，其中 100,722 个 HTML、3,025,051,284 字节；用户提供的约 40 MB 压缩包只作结构参照，未另行打开验证。

项目始终把下面五层分开计数。这是避免“索引有记录”“下载拿到 200”和“用户能浏览”相互替代的核心规则。

| 层次 | 能证明什么 | 不能证明什么 |
|---|---|---|
| CDX 索引 | 某个规范 URL、时间、状态、MIME 或摘要曾出现在索引中 | 不证明当前保存了该实体，也不证明回放会成功 |
| 下载成功 | 收到了响应并保存了请求、最终 URL、时间和响应元数据 | 不证明正文不是错误页、截断体或错误 MIME |
| 实体有效 | 字节、摘要、长度、MIME 和类型检查通过；图片还须由 Pillow 完整解码，ZIP 成员还须通过 CRC | 不证明它是 2008 基准，或一定被页面实际引用 |
| 页面可浏览 | 本地服务器按原 URL 路由提供页面，浏览器得到正文、脚本和交互结果 | 不证明站点的全部历史资源都已恢复 |
| 闭包完整 | 对声明的页面和静态依赖范围，引用、来源和缺口已经逐项对照 | 不证明全站、动态日期内容、Flash 数据或第三方站点完整 |

因此报告中“有 CDX 行”“已尝试”“有效实体”“可浏览”和“闭包完成”始终是不同字段。错误 HTML 即使状态为 200，也不会进入图片有效集合；索引为空、请求超时或本地没有实体，也只表示当前证据不足，不能写成“历史上不存在”。

## 三、从百科入口到有限依赖闭包

**缺口分类更正：**第一轮 17 项请以[17 项缺口复核](gap-review-20261011.md)为准，结论是 13 项错误响应、4 项晚期有效补充。扩展期另有 16 个 CDX 阳性的非图片/错误目标；它们是独立的一组，不是上述 17 项的剩余。后者的本地对照为 9 个 URL 特定错误实体和 7 个仅有索引错误提示，未发现有效而未批准的非图片实体。

第一阶段固定了百科首页和 51 个数字词条，共 52 个核心页面，并从入口、XSL、CSS、JavaScript、iframe 菜单和词条正文提取来源边。静态解析不执行远程脚本；对 JavaScript 只展开有明确字面证据的资源，对字符串拼接、模板变量、注释和示例路径保留为未解析边或排除证据。相对 URL 按浏览器宿主文档解析，不按脚本文件所在目录臆测。XSL 的 import/include 与 XML stylesheet 另行解析；样式表的 @import、url 和旧 IE behavior 也分别记来源。

这一步修正过多次解析误报。topic-list 中拼出的数字 XML 应回到百科文档目录，而不是落在 scripts 目录；XSL 输出模板中的 layout/index.xml、示例图片、注释中的 Flash 和动态 document() 分支不能自动变成已实例化页面；cascade.js 中 url(images/minus.gif)、closemenu.gif 等活动背景则必须按百科文档基址恢复。站内导航可用来解释菜单，但不会因此扩展到其他游戏栏目、广告、分析脚本、帖子或第三方资源。

早期缺口清单经过原始响应、CDX 和页面用途核验，第一轮 17 项（详见[17 项缺口复核](gap-review-20261011.md)）分为 13 项错误响应和 4 项晚期有效补充；其中有些相同错误体因 digest 折叠而跨 URL 重复，不能据此假定 URL 没有捕获。对扩展期独立的非图片候选的本地收敛显示：16 个候选中 9 个有 URL 特定的已保存 404 HTML，7 个只有索引层面的同摘要错误提示；没有发现尚未批准而又有有效实体的非图片资源。该结论见[非图片最终对照](../research/final-gap-closure-20261012/nonimage-final-reconciliation.json)及其验收报告。

用户要求暂停并恢复后，工作分为两条线：保留原始文件和依赖图的采集线，以及由本地服务器和真实浏览器验证的镜像线。Current News、Story、Media、Guide 等新增页面只在有来源页面和官方路径证据时加入；侧栏中的 GAMEGUIDE、MEDIA 等非规范跳转会记录路由拒绝或缺页证据，不把浏览器生成的派生占位 URL 当成原站资源。Sol 研究用于收集同年代回放方法和结构参照，网络工作仍遵守明确的流数、超时、磁盘和重试界限。

## 四、时间、URL 与摘要规则

2008 基准实体优先使用锚点之前最近的有效捕获；同一天稍晚的静态资源单列为 after-anchor supplement，不能静默改写成锚点版本。更早的图片只有在完整、无过滤的 2008 全年 exact/all-status CDX 查询得到空结果后，才可作为 pre-2008 static supplement。查询截断、传输失败、只有 prefix 结果或存在任意 2008 行时，都不足以打开这个门槛。

URL 规范化只处理协议、主机名和默认端口等等价关系，路径、查询串和大小写保持原样；不能用整条 URL 的 lowercase 把不同资源折叠。相对链接按页面宿主解析，保留论坛规则页等获批准子域的真实 host。Archive 的 id_ 和 im_ 回放都记录为不同请求证据；同一实体可用摘要或字节关系连接，但不能伪造另一个 Memento 的响应头或实际时间。

图片必须通过文件签名和完整解码，响应声明的 MIME 错误也要保留。例如一个响应声明为 JPEG、但完整字节实际解码为 GIF 的对象，原 MIME 不被覆盖，只在派生验证记录 served_mime 修正理由。HTML 错误页、通用指南、重定向落地错误体和零字节文件都留在失败证据中，不进入图片 map。所有 ZIP 对象同时核 CRC 和 SHA-256，并在 map 中保存实际文件位置和捕获日期。

有一类旧索引摘要需要特别说明。298 个 pre-2008 静态图片的原始响应正文保持不变，raw SHA-1 与旧 CDX 摘要不同，但 SHA-1（正文加一个 LF）与索引摘要一致。这个关系由本地 15 种变体对照和独立样本确认，验证器通过显式的 allow_pre2008_static_supplement 与 allow_legacy_arc_lf_framing 门禁，要求资源类型、年份、模式和说明全部匹配；默认模式仍拒绝该差异，已有 18 项边界测试覆盖负例。ARC 记录边界是合理假设，却没有取得对应 ARC 原件，不能写成已证实的存储机制。图片字节、原始 SHA、ZIP 和长度都不加 LF、不被改写，旧拒绝报告也不覆盖。

网络请求采用有限批次和最多四条 Archive 流；单实体、总时限、响应体、工作区和磁盘余量都有硬门槛。重试必须有新证据，例如换用不同传输栈、完整响应窗口或发现 id_/im_ 差异；相同失败不能循环重提。每次批次保留 manifest、响应头、最终 URL、Memento、错误原因、部分体和终止状态，避免把“未尝试”“传输失败”“错误实体”和“无捕获”混为一类。

## 五、构建、兼容与浏览器验收

**动态日期的准确范围：**已有代码和[官网资源恢复记录](resource-recovery-2008.md)明确记录两项基准化修复：旧日历使用 2008 基准日期，Toplist 数据日期固定到基准日。Current News 首页的 Screenshot of the Day（SSOTD）也有明确的派生时钟补丁：用 2008-05-12T21:00:44Z 替代本地 HTTP Date，选择 ss1340；这只修复截图编号选择，不能代表所有 Current News 动态数据都已恢复。源页面字节保持不变。

源实体、下载 ZIP、研究报告和派生的 offline/site 分开保存。兼容层只做有记录的现代浏览器适配：修正旧菜单事件的双重切换、提供键盘可用的开闭状态、将无本地索引的站内搜索和 forum/support 目标映射为本地未收录说明，并禁止外网请求。原始 CSS、XSL、JavaScript 的外观和路径优先保留；缺图使用可解释的缺口提示，不从现代资料伪造历史图片。兼容补丁和浏览器诊断保留在独立的 support 与 compatibility 报告中。

旧的 Scriptaculous/Prototype 依赖若以 MIT 许可代码作兼容补充，会明确标成第三方运行库，不冒充 Warcraft 捕获。Flash 或动态日期数据即使找到 SWF、脚本或占位路径，也只能说明资源被保存或依赖被识别；浏览器不再提供 Flash 运行环境，无法据此声称交互恢复。日期修复的准确范围见下方动态日期说明；源页面字节不改。

最终构建包含 8,304 条路由和 917 个页面文档。真实 Chrome 全量检查接受 917/917：当前 build 的页面错误、资源失败、外部请求和 route reject 均为 0；旧的少量 7 页补测只是历史阶段证据，不能替代最终全量轮次。验收、manifest 和浏览器报告见[最终浏览验收](../research/offline-2008/full-recovery/round-109-root-full-browser-acceptance.json)与[最终缺口验收](../research/offline-2008/full-recovery/round-111-root-final-gap-closure-acceptance.json)。页面检查中仍有占位引用，它们是已知缺口线索而不是浏览器失败；总计 5,708 次占位事件，4,581 个属于项目范围，1,127 个为外部范围观察，不能直接当作 5,708 个文件。

## 六、交付状态与边界

图片闭包的最终对照覆盖 407 个冻结目标：81 个 2008 计划目标、325 个通过全年空证明的 pre-2008 补充目标，以及独立的 ss30 资源；其中 70 个为基准 2008、12 个为锚点后 2008 补充、325 个为更早补充。407 个目标均有唯一来源记录，时间或摘要不匹配为 0，重复为 0。详细逐项对照见[图片闭包审计](../research/final-pre2008-image-wave-20261012/post-followup-completion-audit.json)。这表示声明的图片范围已闭环，不表示整个官网已恢复。

最终压缩包为 2,251,344,514 字节，SHA-256 为 66553fcd368ae5ee48dfb9f1b11897ac7fb3fd6a1983a0e303c2c088522c1c63；完整解压后约 5,187,533,088 字节。第一次深层 Windows 路径验证触及 260 字符限制，改用短提取根重新进行 loopback smoke，ZIP CRC、manifest、关键页面、MIME 和本地请求均通过；临时副本随后清理。最终验收记录见[根验收摘要](../artifacts/offline-20261012-root-final-acceptance.json)和[短路径可移植性检查](../artifacts/offline-20261012-recovery-portability-shortpath-check.json)。

工作区最终约 8.73 GB，磁盘可用约 21.57 GB，继续遵守 14 GB 工作区上限及 10 GiB 加 256 MiB 保留量。当前 restoration_complete 仍为 false；页面浏览验收通过不改变这一点。最终缺口按保留 scheme 的 URL 计为 3,358 个目标、按 http/https 等价分组为 3,355 组。缺口包括未获得实体、仍只有索引或页面运行时提出的资源；其中 /pvp/flash-rewards 的真实 404 和一个 Toplist 动态数据项有明确证据，其余须按各自证据分类。缺口报告明确要求：无本地实体或空 CDX 不能证明历史上不存在捕获。

本项目因此可以交付一份有原始证据、依赖来源、可浏览本地镜像和可复核验收链的 2008 百科恢复包；不能交付“整个 World of Warcraft 官网完整归档”，不能把 2010 XML 候选称为可用最新版本，不能把 ARC 摘要推断写成事实，也不能声称原站源码与所有 assets 已统一开源。后续若继续恢复，应从现有缺口和来源边界出发，保持实际捕获日期、原始 MIME、错误实体和派生修复的分离。

发布组织也按证据规模分层：Git 记录部署副本、源码、文档和关键报告；全量大备份与完整研究证据通过 Release 分卷提供，并由清单和相对路径互相定位。原始对话不公开；文档引用的路径应在完整包或 Release 证据中查找。不能声称所有原始证据都位于 Git 主树，主树与 Release 分别承担可审阅代码/文档和大体量取证材料的职责。
